# ADR-010: Precompile Seed Data and Test at Four Boundaries

## Status

Accepted

## Date

2026-07-25

## Context

The source spreadsheet contains multiple sheets and embedded drawings, while the
runtime should stay small and deterministic. Existing tests cover only a few
domain cases and do not exercise persistence, IPC, renderer behavior, or packaged
artifacts.

## Decision

Add a development-time seed compiler that reads `docs/base-cadastro.xlsx`,
normalizes unambiguous records, validates assets, writes a deterministic packaged
`seed-vN.json`, and emits a rejection report for ambiguous rows. Runtime never
parses XLSX and applies the seed only when no user data exists.

Use Vitest Node for pure unit tests, Vitest with a DOM environment for renderer
modules, real temporary filesystem integration tests for repository/assets/IPC
composition, and Playwright Electron smoke tests against packaged Linux `.deb`
contents and Windows NSIS output in their platform jobs.

## Alternatives Considered

### Alternative 1: Parse XLSX on first launch

- **Description**: Package the spreadsheet and an XLSX runtime parser.
- **Pros**: One source format.
- **Cons**: Slower, heavier, and exposes first-run behavior to ambiguous workbook details.
- **Why rejected**: Build-time compilation is deterministic and testable.

### Alternative 2: DOM tests only

- **Description**: Skip packaged Electron smoke coverage.
- **Pros**: Faster CI.
- **Cons**: Cannot catch preload, packaging, icon, or native-operation failures.
- **Why rejected**: The user selected DOM plus Linux and Windows smoke tests.

## Consequences

### Positive

- First launch has no spreadsheet parsing dependency.
- Tests cover pure rules, real local boundaries, UI behavior, and distribution.

### Negative

- Seed generation and platform smoke jobs add CI time and maintained fixtures.

### Risks

- Platform smoke tests can be flaky; use deterministic local fixtures, no network,
  bounded timeouts, and artifact inspection before UI launch.

## Implementation Notes

Fakes are limited to OS dialogs/shell calls and fault injection at I/O boundaries.
