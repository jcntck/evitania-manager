# ADR-008: Generate Trees and Consolidation from One Pure Planning Snapshot

## Status

Accepted

## Date

2026-07-25

## Context

The current planner produces only consolidated rows and reports one global cycle.
The PRD requires per-objective trees, priority stock allocation, continued
processing of valid branches, source estimates, and exactly reconcilable totals.

## Decision

Implement a pure `PlanningEngine.calculate(snapshot)` pipeline. It validates and
indexes the catalog, traverses pending objectives in stable priority order,
allocates a mutable copy of stock, builds immutable `ObjectivePlan` trees with
per-node allocation and unresolved-branch diagnostics, then derives consolidated
rows from those plans. Source estimates are a separate pure pass over missing
raw nodes. Cycle detection is path-local and records the complete cycle without
aborting independent branches.

## Alternatives Considered

### Alternative 1: Separate tree and consolidated calculators

- **Description**: Calculate each view independently.
- **Pros**: Smaller individual functions.
- **Cons**: Stock and rounding can diverge between views.
- **Why rejected**: One snapshot must reconcile exactly across both views.

### Alternative 2: Extend the current global needs map

- **Description**: Add tree metadata to the existing consolidated traversal.
- **Pros**: Less initial refactoring.
- **Cons**: Cannot represent per-objective allocation or branch-local errors cleanly.
- **Why rejected**: The model does not contain the required causal structure.

## Consequences

### Positive

- Trees and consolidated totals share one deterministic source of truth.
- The engine is independently testable without Electron or DOM.

### Negative

- Large plans retain tree nodes and consolidated indexes in memory for one snapshot.

### Risks

- Path explosion can exceed safe bounds; calculation stops affected expansion at
  20,000 nodes and returns a typed limit diagnostic instead of partial silent data.

## Implementation Notes

The CI performance fixture contains 5,000 catalog records, 50 active objectives,
and a 20,000-node expansion; search and planning each complete within 500 ms.
