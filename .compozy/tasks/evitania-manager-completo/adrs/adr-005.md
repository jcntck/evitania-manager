# ADR-005: Distribute Linux Releases as Debian Packages

## Status

Accepted

## Date

2026-07-25

## Context

The original product baseline selected AppImage as the primary Linux artifact.
The product owner has changed the required Linux distribution format to a Debian
package.

## Decision

Every Linux release provides an installable `.deb` package and a ZIP containing
that package. The `<version>-linux` tag publishes these Linux artifacts together
with their required checksums, SBOM, and supported provenance attestation.
AppImage is no longer a product deliverable.

## Alternatives Considered

### Alternative 1: Continue with AppImage

- **Description**: Preserve the original portable Linux artifact.
- **Pros**: Runs across a broader range of Linux distributions without installation.
- **Cons**: Does not follow the product owner's selected distribution contract.
- **Why rejected**: The product owner explicitly replaced AppImage with `.deb`.

### Alternative 2: Publish both `.deb` and AppImage

- **Description**: Maintain both Linux packaging formats.
- **Pros**: Supports Debian-family installation and portable distribution.
- **Cons**: Expands the supported release surface beyond the requested product.
- **Why rejected**: Only `.deb` was requested as the replacement.

## Consequences

### Positive

- Debian-family users receive a native installable package.
- The release contract has one unambiguous primary Linux format.

### Negative

- Linux distributions without Debian package support are not directly served by
  the packaged Linux release.

### Risks

- Incorrect package metadata or desktop integration can produce a broken
  installation; release validation must inspect package identity, icons, and
  installable contents before publication.

## Implementation Notes

The packaging tool and validation commands belong to the TechSpec.
